守卫原来住在 `tools/worktree-guard.mjs`，而 `tools/` 正是会被级联搬走的目录之一 —— **守卫与被保护物同归于尽**：钩子报 `MODULE_NOT_FOUND`，恢复从未发生且无任何提示（日志也写不出来）。CM-007/008/009 + GOV-002 实施时现场复发共四次，同一根因。

## 三层防线设计

| 层 | 位置 | 作用 |
|---|---|---|
| 1 | `scripts/worktree-guard.mjs` | 权威版本（已移出 `tools/`），随仓库分发。ROOT 解析支持 `CALLME_WT_ROOT` + `git rev-parse --show-toplevel` + 脚本位置兜底，不再假设"脚本在工作树里" |
| 2 | `<git-dir>/worktree-guard.mjs` | `selfInstall()` 每次运行自动安装的副本。`.git/` 在工作树之外，级联搬不到它 |
| 3 | `.githooks/*` 内联 | 前两层都不可用时，`git diff --name-only --diff-filter=D HEAD \| git restore --pathspec-from-file=- --worktree` 最小应急恢复 |

钩子按 1 → 2 → 3 依次尝试。判定规则未变（`intended` / `missing` / `collateral`）。
