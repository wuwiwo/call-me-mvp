checkout+merge 后 `tools/` 下 14 个已跟踪文件从工作区消失（`git status` 显示 ` D`），post-checkout 钩子的 `worktree-guard.mjs` 与 `check-worktree.mjs` 本身也被搬走，防线失效。回收站取证（`read_recyclebin.py`）显示 16:08:31 整个 `tools/` 目录被移入回收站——与 `docs/handoff/archive/WORKTREE-FILE-LOSS.md` 记录的级联删除缺陷同源：checkout 更新文件时 unlink 旧版被沙箱 hook 改写为回收站，级联把目录整体搬走；被更新/新增的 3 个文件由 git 随后写回幸存，14 个未变更文件陪葬。

- 恢复：`git restore -- tools/`（只写不删，不走删除路径），恢复后 `git status` 干净、`check-worktree` 缺失 0。
- 教训：**防线脚本入库 ≠ 防线能运行**——guard 自身位于会被级联搬走的目录内。恢复入口是 `git restore`（索引/HEAD 从未损坏）。合并/检出后必须立即跑 `check-worktree`（本次即靠此流程发现）。
