## 任务目标

让 `notification.js` 的已读回执轮询可取消、单一所有权：新一次发送开始时旧轮询立即停止且不得再写状态条，`#receiptStatus` 只反映最新一次发送的回执；单次发送的轮询节奏与超时语义保持不变。对应 `docs/TECH_DEBT.md` CM-001-TD-07（已标记解决）。

## 实现（提交 2f01e57 / f1786f4 / e61e71d / d3ac0d0）

- `notification.js` 新增 `receiptPollTimer`（句柄）+ `receiptPollGeneration`（代际）+ `stopReceiptPolling()`，做法与 CM-006 `countdown.generation` 一致。
- `pollReadStatus()` 启动前先停旧轮询 → 同一时刻活跃轮询 ≤ 1；回调入口、`await fetch`、`await res.json()` 三处代际校验，旧轮询一律直接返回不写状态条（含 timeout 分支）。
- 终态（read 命中 / 15 次超时）先清句柄再写状态条，使「句柄非空」⇔「有轮询在等待」。
- 顺带修复 `setReceiptStatus(state)` 参数遮蔽导入的 `state` 模块 → `statusName`。
- 刻意不用 AbortController（避免改动既有 JSONBin 读取方式，属 NON-GOALS）。
