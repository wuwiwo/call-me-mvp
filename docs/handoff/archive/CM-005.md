## 另一个工具缺陷（已定位，待修）

`tools/negative-input-safety.mjs` 在 `main` 已包含修复后**无法正确自证**：

- 设计意图：回退来源 ref（默认 `main`）若已含修复，应主动 `exit 2` 报「没有可回退的修复」。
- 实际行为：`alreadySame` 守卫用 `readFileSync`（磁盘为 CRLF）直接比对 `git show`（LF），
  **因换行归一化差异恒不相等**，守卫失效 → 脚本继续跑，回退等于没回退，
  最终报「0 条注入类失败 / 不通过」，容易被误读成「修复失效」。
- 修法：比对前统一换行（`replace(/\r\n/g, '\n')`），并让守卫在 ref 已含修复时给出明确提示。
- 同一文件还有一处：`finally` 里的 `rmSync(BACKUP_DIR)` 没有 `try/catch`，
  Windows 上抛 `EBUSY` 会让异常从 `finally` 逃逸 —— 即使验证全流程正确，脚本仍非零退出
  并留下 stale backup 目录（`.workbuddy/cm004_backup` 长期残留即同源）。
  **清理是收尾，不该有否决验证结果的权力。**
